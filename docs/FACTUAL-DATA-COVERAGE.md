# Factual game data coverage

Reviewed 11 October 2026. Backend 0.9.1 and Collector 0.3.1 provide a generic factual interface. The requested-data document is an ideal contract: an unavailable source is explicitly unknown, not a fabricated value. This release does not certify every game mechanic or effective-stat formula.

## Included and excluded

Included: game-derived progression, ownership, reported balances, public resource definitions, market snapshots, observed activities/timers and source coverage. Excluded: personal goals, preferences, player-reported facts, advice history, ranking/recommendation engines, method comparisons and budget reserves. Demo identities/data are synthetic. Each self-hosted instance uses its own application, credentials and private collector; there is no common server or maintainer key.

## Acquisition contract

API profile tools default to cached mode. A first snapshot may be fetched; subsequent reads never refresh it automatically. Snapshot expiry requires an explicit occasional `mode: snapshot` check. `mode: live` is rejected before upstream work; rapid identical snapshot reads are rejected. No background player API polling or API session/history collector exists. Explicit snapshot mode must not be scheduled as a polling loop. Public no-key resource and market endpoints use separate request-driven caches.

`skyblock_live_context` is pollable and reads only fresh, currently observed client data. It makes zero API/identity requests, has no API fallback and never controls the game. The collector samples/exports every second; the optional private bridge checks every two seconds. Defaults require both export and individual observation freshness within ten seconds. Old menu observations stay available in the dated latest-observation tool, but are excluded from live reads. Timers are saved displayed values, never invented countdowns.

## Interpreting coverage

`data_contract` lists generic factual requirements, source evidence and unknown/partial reasons. Domain evidence alone does not certify every individual requirement. `systems` identifies known and new reported systems. Source mappings have explicit omissions, budgets and unverified semantics; inventories are decoded under size/time/memory limits. Lists expose pagination. Known zero, false and empty differ from missing/null. Source timestamps remain separate; conflicting or differently dated observations are not overwritten. A full owned-estate value, live countdown or effective-stat total is not returned without defensible inputs.

The mod does not automatically open bank/storage/progression menus. A passive Minecraft client only receives what the server sends; unseen menu data cannot be recovered by more frequent local polling. Supported menu formats fail closed when ambiguous or changed. In-game verification is distinct from fixture/build/startup checks.

## Sources and rules

- [Hypixel API policy](https://developer.hypixel.net/policies/), updated 30 September 2026: no continuous player API polling/session tracking; cache and protect registered application credentials.
- [Hypixel Allowed Modifications](https://support.hypixel.net/hc/en-us/articles/6472550754962-Hypixel-Allowed-Modifications): owner-visible observations only; no gameplay automation/protocol changes. This is a design assessment, not Hypixel mod approval or a guarantee.
- [Official API](https://api.hypixel.net/): profile/Garden/Museum/own auction/Bingo endpoints and public definitions/markets.
- [Pinned MIT-licensed NEU data](https://github.com/NotEnoughUpdates/NotEnoughUpdates-REPO/tree/79c0356d2117e40f1d75c06861126ebaa38c5af6): XP, nodes, shards and bestiary; bundled license. Arithmetic is evaluated by a bounded local interpreter, with no remote execution.
- [Pinned SkyCrypt counter implementation](https://github.com/SkyCryptWebsite/SkyCrypt-Backend/blob/5252bf610310893598916301753486bc4b13ab7d/src/stats/mining.go): source consulted for reported counter semantics/numerical reference facts; no SkyCrypt code is distributed.

## Daily and Whisper evidence in 0.9.1

- Missing/null evidence is unknown. Experience enchantments use enchantment levels, distinct from skill/pet XP.
- Garden contract coverage includes the separately cached shared Garden endpoint, member Greenhouse snapshot and their distinct retrieval times. Availability of a domain does not certify every requirement.
- Modern `foraging_core.whispers` reports Forest/Desert totals and per-preset `spent` and `spent_non_refundable` counters. Missing counters and selected presets stay unknown. They are not summed across presets or subtracted to invent a spendable balance. Current owner-displayed Forest/Desert balances are separate evidence. Legacy available/spent fields remain supported.
- A supported Commissions menu can establish that a Daily bonus is displayed; that does not establish a positive remaining count. Collector 0.3.3 additionally validates stable, fully parsed reward previews before reporting exhaustion as zero. Empty/partial/loading menus cannot establish zero. Observed completed/claimable-to-fresh-task transitions are counted separately from milestone completions; counts are partial and scoped to the collector run. Bonus replenishment records an observation interval, not an exact reset time or a full starting count. An explicit remaining-count or reset-duration line is captured if supplied. Saved/closed-menu observations do not establish today's state. No fixed reset timezone, four-charge assumption, XP-based completion or continuous API polling is used.
- The live tool requires a current export from the active owner/profile. A running bridge with an old disconnected export is unavailable, even though dated saved observations can remain readable.

Modern Whisper schema reference: [Skyblocker ForagingCore model](https://github.com/SkyblockerMod/Skyblocker/blob/32ed634695a54f97cf8ae2dc234bd7bedfbfcc2f/src/main/java/de/hysky/skyblocker/skyblock/profileviewer2/model/ForagingCore.java). Displayed balance semantics: [SkyHanni HotF reader](https://github.com/hannibal002/SkyHanni/blob/88c8bf2f566f42150e869fe9cc7b78dff05dc086/src/main/java/at/hannibal2/skyhanni/data/hotx/HotfData.kt). Daily marker reference: [NEU commission timer reader](https://github.com/NotEnoughUpdates/NotEnoughUpdates/blob/9b1fcfebc646e9fb69f99006327faa3e734e5f51/src/main/java/io/github/moulberry/notenoughupdates/overlays/TimersOverlay.java). These implementations were consulted for data formats; their code is not distributed in BlockContext.

Commission claim totals now survive restarts in a bounded owner/profile checkpoint. Pending claim candidates and current positive-count coverage are not restored. An exact displayed counter plus continuously observed bonus claims can maintain a positive remaining count until a gap; otherwise it stays unknown. The fixed 05:00 UTC reference and historical four-bonus rule are model metadata, not current server proof. Due HotM checks remain pending when current game evidence is unavailable and can join a separately requested API snapshot without extra API calls.
